Capabilities

Core System Features

Streaming Chunking

Large files are processed in configurable chunk sizes (e.g. 64MB) for memory-efficient streaming across storage nodes.

Configurable Replication

Multi-replica storage ensures continuous file availability even when individual storage nodes crash or go offline.

Integrity Verification

SHA-256 checksums are calculated per-chunk and verified end-to-end to detect and repair data corruption.

Automatic Failure Recovery

Heartbeat monitor detects dead nodes and automatically triggers chunk reconstruction onto surviving healthy nodes.

Resumable Transfers

Interrupted uploads check previously verified chunks on the cluster and resume without wasting bandwidth.

Concurrent Transfers

Parallel HTTP streaming allows multiple concurrent uploads and downloads across cluster storage nodes.

Offline LAN Deployment

Designed to operate completely offline in local network environments without external internet dependencies.

Erasure Coding (Exp)

Experimental Reed-Solomon coding (K=4, M=2) implemented alongside replication for higher storage efficiency.

Current System Limitations

  • Scenarios F2, F4, F6, and F7 were not experimentally executed due to hardware/OS injection requirements.
  • Physical multi-host LAN throughput depends on network switch bandwidth and host hardware specifications.
  • Manager metadata uses SQLite WAL (single-writer concurrency model suited for small to medium local clusters).
  • Erasure coding implementation is experimental; replication factor 2 remains the primary fault-tolerance mode.
  • This Hugging Face Space is a client-side interactive simulation and does not connect to a live backend.
